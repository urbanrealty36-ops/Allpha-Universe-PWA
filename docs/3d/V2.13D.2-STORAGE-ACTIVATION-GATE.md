## Important safety boundary

This phase is **preparation only**. The default command is dry-run and writes only a local activation manifest.

The activation command must not be called until both explicit approvals are present:

`ALLPHA_3D_HUMAN_VISUAL_FIDELITY_APPROVED=true`

`ALLPHA_3D_PRODUCTION_PROMOTION_APPROVED=true`

No service-role secret is used by the PWA/frontend.

## Planned activation contract

For each of the 350 assets:

`theme-v2-real-3d/v2.13/<theme>/<category>.glb`

The asset metadata must retain:

- schema = `allpha-3d-v2-13d-theme-production/1.0`
- `presentationOnly=true`
- `legacy=false`
- `canonicalRenderer=AllphaWorldRenderer`
- source = Blender production export
- lifecycle = staged before activation, active after activation

## Runtime contract after activation

The PWA must resolve assets through the existing backend/runtime asset path and signed URL policy. It must not construct privileged Storage mutations in the browser.

Activation is not considered GREEN merely because files exist in Storage. Runtime signed URL resolution, renderer loading, mobile/browser QA, and security verification remain required.
